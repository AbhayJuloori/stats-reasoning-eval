LLM evaluation · applied statistics

Can open models do the stats, and can they spot when it's done wrong?

150 data questions with reference solutions, plus 60 worked answers with one planted methodology flaw each: peeking, leakage, Simpson's paradox, the wrong test, uncorrected multiple comparisons. Four open models answered and reviewed; an LLM judge graded the reviews and was itself checked.

Flagging is not catching

Each model reviewed 60 flawed answers and 15 correct ones. "Named the flaw" means the review identified the planted mechanism, not just that something was wrong. Three models called every correct answer flawed too, so a flag rate alone would have made them look nearly perfect.

Which mistakes get caught

Share of the 12 flawed answers per type where the model named the planted mechanism. Multiple comparisons was nearly invisible: models invented design problems instead of counting the tests.

Checking the judge

The judge (phi4:14b) was shown each flawed answer next to its corrected version, in both orders. It picked the corrected one far more often when it came second. A larger free model on OpenRouter showed no order effect on 20 pairs.

Picked the corrected answer

Judge versions

v1 read the full rubric and returned a score. v2 parses the review's own verdict in code and asks the judge one yes/no question: did the review name the planted mechanism? Hand-reviewed grades: 80 stratified reviews, each draft score confirmed or changed by hand.

Solving: write a script, run it, check the number

The model sees a data preview and a question, writes Python, and the printed answer is graded against a reference solution with a tolerance. One repair turn is allowed if the script crashes.

QRData paper, all 411 items: best open model 37%, GPT-4 58%. The models here are about a year newer; 99 items gives wide intervals.

How it was graded

Review rubric

2: verdict FLAWED and the issue names the planted mechanism. 1: FLAWED but the wrong or a vague reason. 0: called it sound. For correct answers, a FLAWED verdict claiming a serious error is a false alarm.

Data and models

Hillstrom MineThatData email experiment (64,000 customers, randomized) and QRData benchmark sheets (CC BY-NC). qwen3:8b, qwen3:14b, gemma3:12b and llama3.1:8b via Ollama; judge phi4:14b; second judge nemotron-3-super-120b on OpenRouter's free tier. Solve sets ran on a Kaggle 2x T4 notebook.
